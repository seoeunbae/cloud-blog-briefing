# 🎬 Customer Engineer 핵심 사용 시나리오 (Scenarios)

이 문서에서는 구글 클라우드 Customer Engineer(CE) 분들이 실제 미팅 준비 및 고객 기술 대응을 수행하는 시나리오를 바탕으로 가상 워크플로우를 서술합니다.

---

## 🎬 시나리오 1: 핵심 아키텍처 비교 분석 및 관계 시각화
> **상황**: 고객이 "Cloud Run과 Cloud Functions 중 어떤 것을 써야 할지 고민입니다."라고 질문하여 미팅을 즉석 준비해야 합니다.

1. **질문 입력**: CE가 대시보드 인풋 창에 `"Cloud Run과 Cloud Functions 차이가 뭐야?"`라고 질문을 입력합니다.
2. **하이브리드 조회**:
   - RAG 서비스가 입력된 질문 문장에서 `Cloud Run`과 `Cloud Functions`라는 주요 스토리지 엔티티 키워드를 감지해, 지식 그래프 상에 저장된 이 둘 간의 관계 정보(`COMPETITOR_OF`, `RUNS`, `IS_A`)를 테이블에서 신속 조회합니다.
   - 이와 동시에 AlloyDB 벡터 테이블에서 관련 세부 기술 문서 본문 블록 4개를 수집합니다.
3. **답변 생성**: Gemini 2.5가 두 참조 스트림을 엮어 **패키징 방식(컨테이너 vs 단일 코드), 오토스케일링 거동, 비용 모델, 추천 상황**을 입체적으로 가공해 Markdown 비교 테이블과 깔끔한 설명조로 응답을 도출합니다.
4. **시각적 결합**: 웹 UI 우측의 지식 그래프 판넬에서 전체 GCP 맵 중 `Cloud Run`과 `Cloud Functions`, `Serverless Compute` 노드가 동적으로 골드 색상으로 변하며 연결선들이 하이라이트됩니다. CE는 이 화면을 보여주며 두 아키텍처의 연관관계를 시각적 구조를 기반으로 자신감 있게 브리핑할 수 있습니다.

---

## 🎬 시나리오 2: 마케팅 블로그 발표 자료와 실제 인프라 릴리즈 정보의 교차 검증 (Cross-checking)
> **상황**: 최신 클라우드 블로그 포스트의 신기술 소식을 검토 중인 엔지니어가, 실제 해당 기능이 정식 릴리즈(GA/Beta)되었는지, 제약사항이나 기술 명세서 로그와 정합성이 맞는지 실시간 대조해야 합니다.

1. **질문 입력**: CE가 인프라 아키텍처 및 업데이트 소식에 대해 검색어 혹은 질문을 던집니다.
2. **다중 소스 RAG 조회**: 시스템이 블로그 글 인덱스(Marketing)와 GCP Release Notes(Technical logs) 양쪽 영역에서 고도로 연관된 정보들을 결합하여 답변을 구성해 나갑니다.
3. **이중 컬러 배지 렌더링**: 답변 영역 최하단 참고 지표 영역에 인용된 문헌들의 성격에 맞춰 배지들이 동적 분리 표기됩니다.
   - 고수준 소개 글은 🔵 `[공식블로그]` 배지로 표기됩니다.
   - 제품 릴리즈 상세 정보는 🟢 `[릴리즈노트]` 배지로 분할 표기됩니다.
4. **링크 교차 검증 및 검토 완료**: CE는 화면에서 🟢 `[릴리즈노트]` 배지를 클릭하여 원문 크롤링 소스 링크로 바로 점프합니다. 최신 기능의 정식 버그 패치 및 업데이트 명세서를 원클릭으로 직접 대조해 확인함으로써, 아키텍처 설계 상의 오류를 실시간에 배제하고 신속한 교차 분석을 마무리합니다.
